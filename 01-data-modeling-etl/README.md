# Модуль 01. Проектирование БД, нормализация и ETL

## Цель

Спроектировать реляционную базу данных, нормализовать её до третьей нормальной
формы (3НФ) и собрать ETL-процесс, который загружает «сырые» CSV-файлы
в PostgreSQL.

## Что сделано

Денормализованные данные о клиентах и транзакциях разложены в 3НФ — это
исключает избыточность и поддерживает целостность. ETL-процесс на Python
(`pandas` + SQLAlchemy) выполняет полный цикл Extract — Transform — Load в два
шага:

1. `etl_1.py` — загрузка таблиц-справочников (dimensions);
2. `etl_2.py` — загрузка таблиц фактов (facts).

Скрипты идемпотентны: повторный запуск не создаёт дубликатов. Загрузка фактов
обёрнута в одну транзакцию — при сбое (например, нарушении внешнего ключа)
изменения откатываются целиком.

## Что внутри

- [`schema/`](schema/) — схема БД: DDL-скрипт `Scheme.sql`, описание для
  dbdiagram.io, визуализация и документ с разбором нормализации.
- [`etl_1.py`](etl_1.py), [`etl_2.py`](etl_2.py) — шаги ETL.
- [`run_etl.py`](run_etl.py) — оркестратор, запускает оба шага по порядку.
- [`data/`](data/) — исходные CSV (клиенты и транзакции).
- [`reports/`](reports/) — выгрузки итоговых таблиц из БД (SQL и скриншоты).
- [`requirements.txt`](requirements.txt), [`.env.example`](.env.example) —
  зависимости и пример настроек подключения.

## Как запустить

1. Создать виртуальное окружение и установить зависимости:
   ```bash
   python -m venv .venv
   .venv\Scripts\activate        # Windows
   pip install -r requirements.txt
   ```
2. Скопировать `.env.example` в `.env` и указать строку подключения:
   ```ini
   DB_URL="postgresql+psycopg2://USER:PASSWORD@HOST:PORT/DATABASE"
   ```
3. Выполнить `schema/Scheme.sql` в базе, чтобы создать таблицы.
4. Запустить ETL: `python run_etl.py`.
